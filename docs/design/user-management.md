# 用户管理：团队 + RBAC（定稿，2026-10-29）

> 前身是评审稿 docs/design/user-management-review.md（分支 review/user-management，7fc4e9d）。决定记在 ADR 0011，这里写「评审里的每一条最后怎么处理的」和怎么用。

## 一、评审缺口 → 处理

| # | 评审缺口 | 处理 | PR |
|---|---|---|---|
| 1 | 项目 / 会话 / 任务没有归属和权限 | 项目带 `teamId` + `createdBy`；成员只看自己的 + 共享的，主人看团队全部；删除进回收站 | #101 |
| 2 | 成员能用「本机」Worker | 仅 hub 管理员 + 被单独授权的 hub 团队成员；`can()` 和派发双重检查 | #101 |
| 3 | 授权判断散落 | `access.ts`：`ROLE_PERMISSIONS` 表 + 唯一 `can()` + `visible()`；路由不再判断角色 | #101 |
| 4 | 注册泄露邮箱是否存在 | 先查开放注册和名额；已存在的邮箱返回和成功一样的响应；开放注册默认关闭 | #101 |
| 5 | 没有退避 | 每邮箱 5 次后 1 秒起指数退避、上限 15 分钟、成功清零、不锁死；每 IP 15 分钟 30 次 | #102 |
| 6 | 没有邀请、不能删人 | 邀请（带角色、计名额、可越过）；删人 = 软删 + 匿名化 + 项目转给团队主人 | #102 |
| 7 | 不能改密码 / 显示名 | 个人设置：改密码（要旧密码，踢其他登录，发通知）、改显示名。改邮箱留作后续 | #102 |
| 8 | 安全事件不进审计、没有 IP | 登录 / 失败 / 退出 / 注册 / 重置 / 改密码 / 改资料 / 邀请 / 删人都进审计，带 IP 和 teamId；后台可筛 | 审计 PR |
| 9 | 成员能读任意会话的资产 | 随第 1 条，资产读取按所在项目走 `can()` | #101 |
| 10 | 没有个人 API token | 后续 | — |

## 二、David 的决定（评审第四节）

1. 可见范围：只看自己的 + 共享的；团队主人看全部。
2. 删除项目：团队主人 + 创建者；软删进回收站，可还原 / 彻底删除（不自动清理）。
3. 本机 Worker：默认禁止，hub 管理员可单独授权 hub 团队成员。
4. 注册：默认关闭，走邀请；邀请计入 `HUB_MAX_USERS`，主人可越过。
5. 角色：维持 owner / member 两档；Admin / Viewer 后续加进权限表即可。
6. 删除用户：项目和会话转给团队主人。

## 三、使用

- **团队主人**：账号菜单 →「我的团队」：邀请（邮箱 + 角色，可勾越过名额）、撤销邀请、改角色、删除成员；底部「团队安全审计」看本团队事件。
- **每个人**：账号菜单 →「个人设置」：改显示名、改密码。
- **hub 管理员**：后台 → 审计：按动作（分组或单项）、操作人邮箱、IP 前缀、时间范围筛选；接口 `GET /api/admin/audit?action=&actor=&ip=&since=&until=&teamId=&limit=`（limit ≤ 500）。团队主人用 `GET /api/team/audit`，服务端强制限定在自己团队。

## 四、数据迁移

全部是幂等的 ALTER / 回填：`migrateTeams`（建团队表，老用户和老项目进 David 的团队）、邀请表、`migrateAuditIp`（审计加 `ip`、`team_id` 列和 `audit_by_team` 索引）。老审计记录的 ip / teamId 为空。
