# 创建 Worktree：两种来源，支持单仓和多仓

状态：首版在独立分支实现，默认关闭；未部署。一个产品动作，两种来源，两者均支持单仓和多仓；不迁移已有会话或目录。

## 首版启用与取舍

- Hub 需显式设置 `HUB_WORKTREE_PLANS=1`，Worker 需支持计划协议并建立经过身份验证的连接。未开启时，新入口隐藏，原有会话和工作目录入口不变。关闭开关不会撤销已有计划的目录保护。
- 从已有目录创建、复用已验证项目底座都不访问远端。**首版接口不启用缺底座自动克隆**；缺底座时先用既有入口准备仓库，再回到这里创建 Worktree。Worker 已有独立的 HTTPS 底座原语，但仅配置 `WORKER_PLANNED_BASE_ALLOWED_ORIGINS` 也不会启用 Hub 的克隆流程；启用前仍需完整网络与恢复验收。
- 创建计划的入口在任务的「开始会话」和工作目录的「＋」菜单；后者先选任务。首版不运行项目准备命令，也不提供计划检出的一键恢复或清扫；已确认及部分完成的检出保留，不通过旧入口删除。下文涉及远端克隆、准备命令和完整生命周期的描述是后续设计，不是当前能力。

## 一项动作，两种明确来源

| 创建方式 | 用户选择 | 平台执行 |
| --- | --- | --- |
| **按项目仓库创建** | 目标机器、项目中已登记的一个或多个仓库、起点 | 在目标 Worker 上复用已验证匹配的底座；缺底座时先走既有仓库准备流程。计划内克隆留待后续启用。 |
| **从已有工作目录创建** | 当前 Git 目录，或所选的同机 Git 目录 | 从每个目录实际所属的本地 Git 仓库创建：不根据项目 URL 换仓、不自动 clone 或 fetch；无需 `origin`。 |

两种方式都产出实际的 Git worktree：一仓得到一个可用工作目录，多仓得到一个组合工作目录，各成员有自己的分支和检出。`git clone` 只是在第一种方式下准备底座，不把普通 clone 或空目录称作 Worktree。只想下载、创建空目录或登记现有目录，仍使用项目页独立的「创建工作目录」。新 Worktree 不复制未提交改动，也不是安全隔离。

## 入口、默认值与确认

- **项目入口**或**任务没有明确工作目录**：默认「按项目仓库」。有指定主仓时默认选它；没指定且有多个登记仓库时，由人选，不取清单第一项。**有明确工作目录的任务入口**或**工作目录菜单**：默认「从已有工作目录」，显示该目录和它的 Worker。当前目录不是 Git 或不可用时说明原因，由用户更换来源；不自动回退。换 Worker 清除不再适用的选择。
- **归属**：新入口创建的 Worktree 仍属于一个项目下的具体任务；任务页沿用当前任务，项目页或无任务上下文的目录菜单先选一个有权操作的任务。没有可选任务时提示先去现有入口新建任务；不在后台创建任务，也不引入无任务的临时 Worktree。创建成功不等于 Agent 已启动；成功后可以用已建目录或组 ID 开新会话，Agent 启动失败只重试启动，不重建目录。
- **多仓**：从一个成员开始，用户主动添加，最多 8 个；不自动勾选全部登记仓库。按项目仓库创建多仓时，沿用项目已指定的主仓，不能在本次改主仓；无指定主仓可建单仓，需先设置主仓才能按项目仓库建多仓。本地组合明确选一个主目录；从已有组合进入可预选实际成员和主目录，确认后创建一组新的检出，不嵌套原组。两种来源首版不在同一组里混选。
- **确认**：逐仓显示机器、来源、起点（名称和提交）、新分支、目标路径，标明「主目录 · 会话起点」。项目方式另标「复用底座」或「需克隆」；有克隆时确认写明「将克隆 N 个仓库」。确认复用后底座失效，需要重新确认，不能自动改为克隆。桌面和手机提供相同的选择、确认、失败和恢复能力；手机单列、完整路径可展开，不依赖悬停。未经授权不返回仓库和路径细节。

## 底座、起点与 Worker 契约

以下为完整设计；计划内克隆和准备命令的首版限制见上面的「首版启用与取舍」。

1. **项目仓库方式**：Hub 按所选项目 `repoId` 和 Worker 查询已登记的可用底座；Worker 核对实际 Git 和远端身份，不只信 `repoUrl` 字段或目录名。有多个验证匹配的底座时列出路径，请用户选；不取最近或最老的一份。复用时优先提供项目该仓库配置分支的本地已知提交，标明「本地已有」，不当成远端最新；未配置则用所选底座当前提交。配置的分支不存在、同名候选引用指向不同提交时，由用户明确选起点，不静默回退。缺底座时，仅在现有授权下对同一登记仓库解析所选远端分支（未指定时用远端默认），预览标明「远端」；确认后才克隆。起点在预览时解析为确切提交，执行前验证；远端计划已变化则重新确认。克隆先写入本操作独占的临时位置，不接管或递归清除别人已有的目录；验证完成后再发布为可复用底座。用户和 Agent 都不选择凭证，不新增或借用其它仓库的权限。
2. **本地目录方式**：Hub 验证明确的来源目录 ID 与任务、项目、Worker 及访问权；Worker 根据实际路径解析顶层和 Git common-dir。默认起点是来源当前提交（支持 detached HEAD）；同一 Worker 上不同路径若指向同一 Git common-dir，只能算一个成员。来源、Git 身份或已确认的引用发生变化时要求重确认。新检出必须在平台管理的安全目标根下，不得嵌在来源目录里；不能只用字符串路径判定。首版自动检出不联网、不跑仓库 hooks、不递归初始化子模块；缺本地对象或无法保证不触发自动取对象时明确拒绝。
3. **共享执行**：两条路只共享「经验证的 Git 身份 + 精确提交 → 新 Worktree」原语。执行和恢复前重查权限、归属和目标状态，同一 Git common-dir 的平台变更串行；完成时核对实际规范化目标、Git worktree 注册、同一 common-dir、分支和起始提交。common-dir 用于实际核验、去重和加锁，不作永久仓库 ID；也不把 common-dir 的父目录假定为底座。普通旧建树路径会隐式 fetch、换用远端引用或回退，不能直接拿来执行这份确认计划；可参考[现有派工精确检出](../../packages/node-gateway/src/git-workspace.ts)的校验，不把它要求远端的流程套到本地模式。区分 `sourceWorkspaceId`（用户从哪儿发起）和 `baseWorkspaceId`（恢复与清理所用的稳定登记底座）。在同一 Worker 找不到经过验证的稳定底座时，首版明确不支持该来源，不能用临时检出冒充底座。恢复是独立动作，不抢占显式新建，也不能在恢复失败时把会话标为可用。
4. **准备命令**：作为独立阶段，确认时明确展示。项目仓库方式可沿用现有项目配置；本地目录方式默认跳过，即使项目 A 配了命令也不自动在 B 上运行。只有用户明确选择执行且符合既有权限时，才按所确认的命令运行。多仓须等全部检出成功后，只在主目录执行；它不在「本地检出不联网」的承诺内。已确认配置后来变化，要重新确认，不以新命令替代旧计划。

## 多仓模型与失败可恢复性

- **先确定成员身份，再扩展本地多仓**：沿用 [`WorkDirGroup`](../../packages/domain/src/workspace-group.ts) 的容器布局，多仓以主成员的真实目录为 cwd，附加仓在 `../repos/<name>` 下。新组用预分配的输出 `workspaceId` 识别成员和主成员，成员来源显式区分 `projectRepoId` 与 `sourceWorkspaceId`，不拿项目登记 ID 当本地组键，也不造假登记。旧组继续按原字段兼容读取。落地需同步检查组存储、会话落点、文件／改动／Git／检查点、追加、恢复与清理；首版本地组不通过旧的「添加项目仓库」入口扩容。远端凭证授权不继承本地来源：新本地来源会话不得靠远端 URL、底座或「项目只有一个仓库」默选 `project.repo.read`；如需读取已登记的远端，必须显式选其 ID，仍需原有授权。
- **先落实读取和授权边界**：新组合来源入库前，组合详情、创建时引用旧组、追加与重试均按所属项目校验，内部 Web API 与 OpenAPI 只投影约定的字段，不把存储对象直接返回。给 Agent 的本地仓库说明用实际目标与相对成员路径，不把项目 A 误当 B 的远端，也不披露源绝对路径、Git common-dir 或凭证。浏览器计划可向有权选择该来源的人显示必要的目录信息。
- **先记录计划，再做有副作用的步骤**：确认后持久化操作 ID、任务、Worker、确切来源、起点、输出成员、目标路径／分支以及每仓预期复用或克隆。同一操作 ID 只能用于同一份计划；改变来源等参数需新确认，不覆盖部分完成的结果。任何成员失败仍可用原 ID 找回计划和进度；区分底座、检出、准备命令、会话启动四个阶段。成功成员不能因另一个失败被标成未创建。只有全部成员检出并满足准备条件才可以按组开会话；不允许直接用组成员 `workspaceId` 绕开整组检查。
- **失败、未知和取消不同**：只重试已经确认未完成的步骤，重新核验同一份计划；超时或掉线先对账，不能以目录或分支重名认领成功，也不自动生成新操作。无法证明归属则停下，不擅自删除或重试。确认前退出不做写入；提交后离开只关闭界面，已克隆底座、检出和分支保留，清楚标明未完成的步骤。半成品和未知操作不得被普通清扫当作孤儿递归删除；显式清理仍遵循终端、未提交修改、检查点及基座保护。
- **保护待使用结果**：新建结果在首次成功启动会话前保持「待使用」，包括 Agent 启动失败；[自动清扫](../../packages/domain/src/use-cases/workspace-cleanup.ts)不能仅凭「干净／无会话」把它判为孤儿。首版首次使用后仍保留检出，不交回旧清理流程；独立清理入口留待后续设计。

## 实施顺序

1. 做共同的可寻址计划、精确检出／核验和清理保护；先接两种单仓来源，保留旧的无来源 `workspaceMode` 和按仓库指定接口的既有语义。
2. 按项目仓库的多仓使用新计划和同一执行边界，复用已验证的布局与成员展示，不原样复用会重选底座的旧重试。
3. 通过成员键与授权兼容检查后再接本地多仓；四种组合都过验收才算完成统一入口。既有会话不换 cwd；现有薄 CLI 的已有目录启动不自动 clone 或创建 Worktree。

## 验收

| 证据 | 验收条件 |
| --- | --- |
| 真实 Git：项目单仓和多仓 | 仅克隆已确认缺底座的仓库；多底座不静默选择；下次可复用。检出提交不受同名分支影响，组内主目录及附加仓正确。验证底座失效、远端起点变化、克隆失败不破坏已有目录。 |
| 真实 Git：本地单仓和多仓 | 绑定 A，选 B 或 B+C，从实际源和提交创建，无远端请求。验证无远端、linked worktree、detached HEAD、未提交改动不复制、缺对象不联网、拒绝跨机器和重复 common-dir。 |
| 兼容与授权 | 获授权的旧组读取、cwd、成员定位与清理不变；新组按真实成员处理文件、改动和检查点。跨项目不允许引用或改组、不披露来源；本地来源不能默选 A 的远端访问，有授权且显式选择才可读。 |
| 失败与重试 | 附加仓失败保留主仓，主仓准备失败保留全部检出，不能用成员 ID 绕过整组就绪；掉线后按原操作核对，不重复克隆、不误认重名分支、不自动重跑结果未知的准备命令。创建后未启动或启动失败，清扫后仍可复用。底座不符时恢复失败，不能显示已恢复。 |
| 桌面／手机 Playwright | 同一入口明确两种来源，单仓和多仓能确认真实计划；普通「创建工作目录」保留下载、空目录和登记，不自动创建 Worktree。Agent 启动失败后能复用结果。 |
