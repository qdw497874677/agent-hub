# 设计调研：多台 Worker 的界面

> 目标：让「任何机器都可以登记成 Worker」这件事在界面上**存在感刚好**——多机用户一眼看清哪台在线、会话跑在哪；
> 单机用户完全感觉不到它。

## 看了什么

| 产品 | 机器 / 执行环境怎么呈现 | 拿来的 | 不拿的 |
| --- | --- | --- | --- |
| Tailscale admin · Machines | 一行一台：状态点、名字、IP、OS、「Last seen 3m ago」；细节点开 | **状态点 + 名字 + 最后在线**的一行式；离线不删，只变灰并给时间 | 表格的多列密度（我们是侧板，不是后台） |
| Vercel / Railway | 部署卡片上一枚小 region / service 徽标 | 卡片上**一枚徽标**说明「在哪」，不占一行 | 彩色环境标签——和状态色冲突 |
| Cursor background agents / Codex web / Claude Code web | 新建时选环境（repo/机器），之后只在详情里出现 | **只在创建时选**，之后跟着会话走，不提供「迁移」 | 云端环境配置流程 |
| Devin / Conductor | 每个会话一个工作区（machine/worktree），侧栏列出 | 会话 = 绑在一处执行环境的一次尝试 | 隐藏底层机器——我们的用户就是要选自己的机器 |
| Vibe Kanban / OpenCode Web | 单机，执行器在设置里 | 单机时零额外 UI | — |
| Warp / Raycast | 命令面板 + 紧凑弹层，Esc 关、点外面关 | Worker 面板做成**顶栏弹层**，键盘可关 | — |
| Linear | 分段选择器（radio pill）代替下拉 | 选 Worker 用**分段 pill**：2–4 台时一眼看全，离线的禁用但可见 | — |
| tldraw / React Flow Pro | 画布节点上的角标信息 | 会话卡 header 里与 agent 名并列的小 chip，不新增一行 | — |

## 落到 agent-hub 的规则

1. **只有一台时不出现**：WorkerChip、WorkerPicker、项目行里的机器名都以 `workers.length > 1` 为前提。顶栏徽标退化成「● 本机」。
2. **状态只用两种色**：sage = 在线、rust = 离线（沿用 visual-direction 的语义色），不给机器分配身份色。
3. **离线可见、不可选**：离线 Worker 留在列表里（最后在线 + 原因），在选择器里禁用。
4. **创建时选，之后不变**：项目选「目录在哪台机器上」；会话在未绑定的项目里可选或「自动」，绑定项目里只展示不让选。
5. **一行讲清，点开看细节**：面板每行 = 点 · 名字 · (本机) / 一句状态（在跑几条会话 · 哪些 agent，或 离线 · 多久前 · 原因）；展开才看 ID、主机、可用目录。
6. **加机器的路径就在面板底部**：一句 `scripts/install-worker.sh` 指向文档，不做向导。
