# 工作目录标签与独立终端

状态：首版已实现并通过本地验收，默认关闭独立终端。参考 [Orca 工作树标签](https://github.com/stablyai/orca/blob/a91fc0a676e324b2630a78bdc6d885f513cc9d88/docs/site/content/docs/model/tabs-panes-splits.mdx#L8-L53) 和[手机标签入口](https://github.com/stablyai/orca/blob/a91fc0a676e324b2630a78bdc6d885f513cc9d88/mobile/src/session/tabs/MobileSessionTabBar.tsx#L135-L245)，不照搬分屏和排版。

## 用户能做什么

- 项目侧栏和列表仍用于查找「工作目录 → 任务 → 会话」。工作目录的入口不再依赖有无会话；没有会话也能进入目录并开终端。任务仍关联会话，终端没有任务。
- 桌面在内容区显示一条同目录的混合标签栏；手机显示「当前标签 · 数量 · ＋」，从列表可以切换和关闭。`＋` 可新建终端，也可新建会话；会话沿用当前登记目录，不默认准备仓库。文件、改动、预览保持会话内工具。保留既有会话直链和草稿。
- **关终端标签就是结束 shell**，关闭成功才移除；回执不明时保留「关闭待确认」并自动对账。`＋` 总是新建终端，不是恢复。关会话标签只退出视图，既不停止 Agent，也不删除记录。
- 切换、退出目录视图、刷新和网络中断只分离浏览器连接；有原进程才接回。Worker 重启、终端退出或空闲回收确认后显示已结束，不凭连接中断推断退出。标签布局和选中状态按账号、项目和目录在本设备保存；实际终端由 Hub 记账，只有创建者可读取、连接或关闭。

## 身份、权限与进程

- 范围：已登记、可用且归属可证明的单目录。组合组及其成员不作为独立终端目标，缺目录的老会话不回退到项目默认目录。Hub 以工作目录 ID 查实际机器和路径；浏览器不能提供 cwd、命令、启动环境或 Worker 替代值。Worker 再验证路径和本机策略。
- 空 shell 可执行 Worker 用户能执行的操作，**cwd 和 `WORKER_ROOTS` 不是沙箱**。首版默认不授权，要求真人登录、项目可见、目标机器访问，以及管理员部署配置对该真人与该 Worker 的精确 shell 授权；只读、项目管理、普通 `worker.use`、API/Bot 令牌均不隐式授权。重新连接和已连接输入须按当前权限处理。沿用 Host／Origin、登录态、有限帧和背压；终端输出不进会话事件、不参与预览端口发现、不记录命令或输出。一个终端只允许一个浏览器输入连接，不抢占。
- Hub 先持久化授权后的创建意图（终端 ID、创建者、项目、工作目录、Worker、状态；不保存输出）。重复同一创建请求返回同一登记，不因响应超时重复建 shell。Worker 管理 PTY，区分开新进程和只接回；接回不存在的 ID 绝不自动创建。终端 ID 与旧会话终端隔离。保持 Worker 配额、有限滚屏和默认 30 分钟空闲回收。
- 持久状态区分 `pending`（已登记）、`running`（已确认开过）、`closing`（已请求关闭）、`ended`（确认不再运行）；在线和是否可接回另由当前 Worker 证据判断。Hub 重启后读持久记录并与当前 Worker 实际清单对账，关闭请求存在时优先关闭；清单中仍有且匹配同一目标才可接回。Worker 断线或迟到回复不能把已关闭记录恢复为运行。没有授权的现存 PTY 不接受输入，应结束并保留关闭意图至确认。
- Worker 在同一顺序域处理创建、关闭和清单快照，关闭封住迟到创建；关闭只以托管 shell 退出为确认。清单须来自当前连接、且覆盖先前操作；换 Worker 进程后，仅仅找不到 ID 不是旧 shell 的退出证据。没有确定凭据时保留占用和「待确认」，不推断远端存活，也不承诺回收用户另行脱离的后台进程。首版没有自动解锁不明状态的操作。
- 登出或登录失效断开那条浏览器连接；项目或机器 shell 授权撤回则连已分离的终端也要进入关闭流程。输出、回放、输入、改尺寸均受当前授权和连接归属约束。Worker 启动环境使用最小白名单，不继承 Hub/Worker 凭据。

## 目录保护与迁移

- 创建意图到 PTY 确认结束期间，占用随登记存续。开终端与删除目录、取消关联、转移、项目删除和自动清理须经过同一准入保护；任一方先获得准入，另一方必须重读当前归属和记录。运行中、请求不明或关闭待确认不能被强制清理绕过。Worker 离线时也不以空清单当作终止证据。
- 应用可能递归删除目录的操作，包括部分 Git 准备失败时的回滚，都先记录目录身份、机器和路径；确认操作结束或未派发才解除，Worker 回应中断或 Hub 重启不解除。首版不能证明软链接、不同 Worker 或挂载对应的物理目录完全独立，故 Hub 不并发执行这类操作与独立终端；同机或跨机重新登记都不绕过。标记不触发补偿删，后续可增加有证据的恢复操作。
- 默认不开启独立终端。先升级可能执行目录变更的 Worker，再用 `HUB_WORKDIR_TERMINALS=1` 重启 Hub。保护开启后，只向已验证支持新目录变更协议的 Worker 派发可能删除目录的调用；旧 Worker 返回明确的不可用，不把旧协议的失败当作完成回执。目标 Worker 另需设置 `WORKER_WORKDIR_TERMINAL=1` 才提供独立终端；默认继续提供旧会话终端，已迁移的 Worker 不因缺少账号授权而回退旧入口。Hub 用 `HUB_WORKDIR_SHELL_GRANTS`（由 `userId`、`workerId` 对象组成的 JSON 数组）给确切账号开通。已有会话终端连接可自然结束，不迁移活进程。首版不做组合目录、分屏、拖拽、共享写入或跨设备同步布局。
- 关闭 Hub 开关只停止新建；重启时如果仍有未结束的终端或未确认的目录操作，Hub 继续对账和保护，不会清空占用。回滚旧 Hub 前须确认所有独立终端已结束、相关 Worker 清单为空、没有未确认的目录操作。任何相关 Worker 离线或仍有待确认时不得回滚至不理解占用标记的版本。无存量占用、未启用新功能时保持原来的目录操作行为。

## 通过条件

1. 桌面和手机从零会话的登记目录启动真实 PTY，验证 cwd；切换到会话后再切回 PID/进程状态不变，草稿不丢；Agent 结束不杀独立终端。
2. 关闭终端实际结束进程；模拟丢回执、断线、刷新、Hub 重启和 Worker 重启，区分同一 shell 接回、关闭待确认、已结束；无静默重开。
3. 不同真人、无 shell 授权、跨项目目录、越界路径、旧 Worker、第二写连接均被拒绝或明确不可用。撤权后不能继续输入。
4. 开终端与目录清理/删除、移除归属竞态不会产生误删或孤儿终端；组合目录、旧会话终端、会话预览和新建会话仍按原规则工作。
5. 按 [测试与验收](../testing/README.md) 执行：领域/存储/桥接确定性测试，真实 Worker 的隔离 Playwright（桌面与手机，含短视口和至少一个断连场景），合并态 `npm run ci`。生产发布不在本轮。
