# 项目会话 MCP：能力与实施计划

## 目标

让人启动的会话通过**当前项目**的 MCP 管理项目资产、创建任务、为新任务或已有任务开独立 Git worktree 会话，以及向同项目会话交接。持久工作空间是一个使用场景，任务绑定与无任务会话都能使用项目级能力。产品不内置「开发」「审查」「验收」角色，不规定顺序，也不规定审查后自动做什么；这些由当次提示词、项目资产或其他扩展决定。

参考场景：用户在同一项目手动建立两个长期工作空间，各开一个任务和会话。开发会话用 MCP 创建子任务并派工，自身只做计划、调度和审查。需要验收时，它把选定的完整 SHA 和验收要求发给另一条会话。验收会话在自己的目录验证，结果通过会话消息回传。无需平台理解「开发」或「验收」的含义。

## 能力和接口

工具名为设计暂名；请求中的对象 ID 不是授权依据。会话内工具走现有 ToolGrant MCP，不把用户的开放 API token 或 Cookie 发给 Runtime，也不把 bot 路由任务工具改成人的工具。

| 能力 | 首版契约 | 复用及新增 |
| --- | --- | --- |
| 项目资产 | 列出当前项目的有效资产及来源，读取允许访问的版本；创建、更新项目自有资产，启用/停用当前项目的资产。不得修改上游共享原件或绕过团队发布审批；资产修改不热更新正在运行的会话。 | 复用资产领域用例和版本/快照逻辑；补会话内 provider。资产组合与跨项目发布不作为首版前置。 |
| 创建任务 | 当前项目的标题、目标，及可选 `parentTaskId`。返回任务 ID/链接；不隐式创建会话或派工。父任务必须在同项目；旧任务默认无父级。首版关系在创建时写入，不开放换父级。 | 新增 Task 的显式父级关系和可查询的子任务；现有创建入口继续兼容。复用普通任务创建，不走 bot 路由审批或自动调度。 |
| 开 worktree 会话 | 必选同项目 `taskId`、`repoId`、`baseBranch`，显式选择执行配置；首版使用源会话所在、已授权且与目标仓库匹配的长期工作空间。返回派工、执行会话和工作区 ID、分支与基线 SHA，执行会话可在工作台打开并显示来源。 | 从现有派工抽出严格 worktree 准备、会话创建、持久记录与交付。保留「注册主会话提案＋人工确认」与「已授权会话直接执行」两个入口；后者不要求普通任务会话注册成主会话，也不借用 `agent.spawn`。 |
| 同项目交接 | 列出调用者可见的同项目会话，向明确的会话 ID 发送交接说明；可附候选标识、任务 ID 和验证要求。调用方显式选择仅投递收件箱（默认）或排队唤醒。唤醒只是交付一轮消息，不替对方切分支、开会话或启动测试。 | 复用现有消息权限与 `wake` 语义，不需要 fork 或迁移会话；不因消息正文出现「通过」等文字自行触发其他动作。 |

### 开工失败时先检查什么

- 创建子任务和启动 worktree 会话是两次操作。拿到子任务 ID 只代表任务建成；如果提示来源没有可复用的长期工作空间，在同一项目关联现有 Git 目录，然后从绑定该目录的会话重新发起。仅授予会话「开 worktree 会话」权限不会为它换目录；纯聊天的空工作空间也不能充当仓库来源。
- `agent.spawn` 指定 `workspace_mode` 或 `repo_id` 时，未传 `worker_id` 就跟随来源会话记录的机器；若只在绑定工作空间上有可用的机器记录，就用该记录。机器无法确认、不在线或无使用权限时不会静默改到 Hub；可显式选择一台有权限、能访问仓库的 Worker。
- 严格派工用 SSH 仓库时，只从登记的地址读取基线，不使用 HTTPS 令牌，也不开放 SSH 发布。请在**实际执行的 Worker 服务账号**下配置已核验的主机密钥，并用默认 SSH 私钥或服务可访问的 `ssh-agent` 提供身份。严格派工不读取 `ssh_config`，因此仅配置在 `Host` 别名、`IdentityFile` 或 `ProxyJump` 里的设置不生效；不会自动信任新主机，也不会切换协议重试。

### 候选提交如何交付

- **通知和提交可达是两件事。** 首版支持同一个 Worker 上的独立仓库：以已登记的派工执行会话、仓库 ID 和完整提交 SHA 标识候选。平台解析双方登记的工作空间，复核同项目、同仓库、同 Worker，以及当前用户对来源的读取权限和对目标的使用权限。不接受模型直接提供本地路径、任意远端地址或 Git 参数。
- **导入是独立、显式的操作。** 接收会话持有单独的 `candidate:import` 授权，并以自身为目标调用 `project.candidate.import`；工作空间由服务端从该会话解析，不接受模型指定。导入只写 `refs/agent-hub/imports/<接收会话 ID>/<完整 SHA>`，不切换接收目录、不覆盖现有分支、不隐式推送。验收会话准备好后自行检出，跑测试前校验实际 `HEAD` 等于候选 SHA。跨 Worker、提交缺失或身份无法确认时报告阻塞，不用分支最新提交代跑。只发消息不等于授权导入。

## 授权与安全边界

- **项目由服务端绑定。** 跨项目操作在工具入口拒绝：对任务会话核对任务项目，对无任务会话核对不可变来源；两者同时存在但冲突则拒绝。不从当前目录、资产文本、默认项目或模型传入的 `projectId` 推断身份。每次调用复核会话、绑定人和当前权限；遇到权限撤销、项目漂移或主体不明直接拒绝。
- **直接执行是显式授权，不是提示词识别。** 由用户在会话上启用该项目的能力，读、任务写、资产写、开 worktree、发送消息分别限权；默认不放开项目写操作。提示词决定如何使用已授权能力，但不会签发授权，也不能由资产或工具输出打开权限。启用了直接创建后，不再要求每个派工点网页确认；现有提案＋确认路径继续保留，未经直接授权不能靠它绕过确认。
- **子会话不继承调度授权。** 新执行会话可继续对话及完成自身任务，不复制父会话的项目写工具授权，也不获得推送、开 PR 或任意跨项目操作权限。现有完整 SHA 发布审批保持独立；不对任意 shell 或环境中的外部凭据作超出平台边界的保证。
- **先补默认工具的授权缺口。** `withToolAccess` 目前会把 `extraScopes` 与默认工具权限合并，给子会话不加新 scope 并不等于禁用了旧写入口。首版先让新 worktree 会话使用显式的最小工具策略，并验证旧的 `agent.spawn`、建任务和 Git 工具不能绕过；普通会话维持现有默认行为。项目级写工具另检查当前会话的显式授权，不把长期外部 API bearer 注入 Runtime。外部 MCP 如需对齐，后续复用领域契约，单独设计凭据和授权。
- **写入必须可追踪、可重试。** 请求键绑定人、源会话、项目和操作，不绑定短期 token；重托管后可复用，但旧 token 不能绕过当前授权。重放先鉴权；同键同参数返回原结果或在途状态，同键异参拒绝，不同源会话互不占键。创建任务与开 worktree 是两次独立写入，开工失败不会删除已建任务。开工先持久化预留 ID 和参数，再创建工作树、启动会话、交付说明。每个未发出的副作用步骤开始前重查授权；撤权后不再推进。已发出或结果不明的步骤保留记录供核对，不盲目回滚、重派或自动重复创建。审计记录人、来源会话、目标、请求键和结果，不记录凭据。

## 实施顺序与门禁

1. **先通最小链路：普通任务会话 → 子任务 → 独立 worktree 会话。** 只先补这条链需要的授权、父级关系和共用派工底座。用真实 Hub、Worker 和 Git 验证两个执行目录隔离、源目录不变、请求重放不重复建任务或会话；同时覆盖无任务会话、跨项目、撤权、旧工具绕行、子会话不继承和提案流程回归。
2. **再通候选交付与交接。** 先证明同 Worker 上两个独立 clone 可以交付未推送的确切提交，再覆盖仅投递、显式唤醒和重复请求；验收前校验实际 `HEAD`。用确定性测试断言缺提交就阻塞、仅投递不唤醒、状态变化不会自动派工或交接。
3. **最后接项目资产写入。** 接入读取、项目自有资产写入与项目启用状态；验证共享资产不能被覆盖、团队审批照常、生效边界保持启动快照或显式升级。
4. **组合验收。** 用真实浏览器跑两个长期空间的场景，两种提示词分别演示「审查后只汇报」和「交接指定 SHA，验收会话按该提交跑浏览器测试」。这验证能力可组合，不拿提示词当权限测试。发布若纳入验收，走独立批准并用专用 GitHub 仓库核对草稿 PR 的 base、head 和完整 SHA，不部署阿里云或合并 PR。报告分开标明 Runtime、GitHub 是否使用替身；原派工验收清单见[持久工作空间派工](workspace-delegation.md)。

### 资产工具的实现边界

- 列表和版本读取先验当前项目与资产可见性，再复用现有版本存储。有效列表只表示已发布候选；待审结果由提交回执显示，不能因此成为可激活版本，也不能按任意摘要读取未发布内容。
- 创建和修订走现有提交与审批，不提供直接发布、固定版本或修改团队共享原件的入口。项目启用开关影响其他人的后续会话，仅项目归属人或项目所在团队的负责人／管理员可改，还需具备当前项目更新权限。
- 资产写入使用本页同样的请求键边界。涉及归档文件和审批记录时，先持久化占位；无法确认结果则回报在途或待核对，不把重试当成新提交。摘要或回执可入记录，正文不入审计。
- 会话需要独立开启 `project:read` 才能调用 `project.asset.list` / `project.asset.read`，独立开启 `asset:write` 才能调用 `project.asset.create` / `project.asset.revise` / `project.asset.set_enabled`。写授权不隐含读授权。读取支持已发布的固定版本清单及 ≤64 KiB 文本文件；`set_enabled` 的 `null` 表示清除项目覆盖值，恢复默认。

现有提案与网页确认路径不因这些工具而改变。
