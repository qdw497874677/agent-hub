# 开发服务：按机器和工作目录查看

服务属于运行它的 Worker 和工作目录，不属于某个会话。会话可引用服务，但不会因此获得访问权限，也不会替用户开放端口。

- 从会话或工作目录打开「开发服务」：桌面是右侧面板，手机是底部抽屉。面板列出当前账号可以查看的机器，默认展开当前工作目录所在机器，当前工作目录排在该机器内第一位。其他机器可独立展开；离线与无结果分开显示。
- Hub 只读查询 Worker 的监听端口。只展示能唯一确认到已登记且有权查看的工作目录的端口；无法确认归属的服务不显示。旧 Worker 缺少必要的目录证据时显示暂不可用。列表不返回命令行、进程、物理路径或监听凭证，也不根据端口猜是前端还是 API。
- 「引用」只向当前工作目录的会话草稿追加服务标识，不自动发送，不携带预览地址或令牌。会话里的引用会重新检查服务与当前查看权限，服务停掉或换进程后，旧引用不会打开新服务。
- 「打开」和手填端口／起始路径使用同一套校验。手填只在当前目录有打开能力时可用，要求端口确实属于该目录；起始路径不携带查询串或片段。没有回执时先刷新查看结果，不自动重复提交。旧[会话预览](preview.md)仍保留，权限、映射及分享与开发服务分开。

## 首版开放范围

列表与引用不要求打开能力。新「打开」只供可信本机试用：Hub 和浏览器在同一台可信机器，Hub 绑定 `127.0.0.1`，入口为 `http://127.0.0.1:<Hub 端口>`，并显式设置不与 Hub 或旧预览重叠的 `HUB_DEVELOPMENT_PREVIEW_PORTS`。远程入口不生成打开地址。上游为已证明身份的 Worker 回环监听，不开放任意主机，不自动分享。端口分配持久保留，不将曾使用的浏览器地址重新分给不同服务；预留用尽时拒绝打开。

浏览器使用不同于 Hub 的主机名，启动链接一次有效；目标服务收不到 Hub 登录 Cookie。新 HTTP 请求和 WebSocket 握手会复查登录、目录和监听身份；不会强制终止已打开的 WebSocket 或 SSE。浏览器 Cookie 不按端口隔离，因此此试用模式不适用于其他本机监听器不可信的环境。公网或 Tailnet 的新「打开」需要另行设计独立、受保护的浏览器入口，不沿用本机试用配置。
