# Agent 运行记录：证据与覆盖范围

运行记录是只读视图，不参与投递、派工或回合收尾。沿用 [ADR 0033](../adr/0033-connector-dashboard.md) 的列表、详情与关系契约；不同来源可以出现在同一列表，但不能据此拼成同一条调用链。

## 第一阶段：普通会话的一条送达

一条 Agent 记录以提示词的送达 ID 标识。队列行提供排队、发送中、已送达、未送达和已撤回等事实；它不证明 Agent 已经开始执行。只有同一会话中、提示词序号之后、携带相同送达 ID 的 `ended` 才能证明这一条的回合结果。结束结果和队列状态独立展示：例如结束事件已写入，但队列仍在收尾，或运行时明确报告结果待确认。

同一会话中，B 可能在 A 结束前就排队并写入日志。因此，不用回合号、时间邻近或两条日志之间的内容反推因果。不把旧版「已送达」当成结束证据，也不把历史未记录当成失败。队列的最后更新时间并不是模型开始或结束时间，不能用它算模型耗时。

列表先按项目范围筛选并限制读取量，再按当前会话的读取权限复核；直接打开记录也执行同一权限检查。任务会话以任务项目为准，冲突的项目绑定不展示；无任务会话首版只用创建时保存的项目。响应不包含提示词、附件内容、工具参数、运行时原始错误、密钥或凭据。

发起类别只读同一会话、同一提示词序号上由 Hub 入口保存的枚举：账号、令牌、系统或未知。系统表示平台代为提交（如调度或派工），不代表背后没有人；没有可信来源的旧记录和混合入口显示「未记录」。不从作者、令牌名字、会话创建者或请求正文推断类别。

## 第二阶段：调度与派工

按当前归属人、项目和任务的读取权限展示调度与派工记录。预留的执行会话 ID 不是已创建的会话。会话链接要求记录的 ID 确切存在、同任务同项目且当前可读；派工还沿用原页面的执行身份条件：只有登录的派工归属人能打开由自己创建的执行会话，Bot、侧聊与有父会话的记录不算。没有链接不影响已获授权的派工记录展示。调度领取和派工准备不是运行时开始或结束；调度的通知标记不是收件回执。回复正文、派工指令、执行路径和原始失败内容不进入运行记录。

派工详情通过同一执行会话权限后，分别列出最近 20 条验收和 20 条发布尝试，超出标为截断。证据只取派工 ID 精确相同的持久化记录，显示完整 SHA、记录时间与已存状态；发布结果不确定不等于失败。即使两条记录的 SHA 一样，也只说明记录的是同一版本，不表示验收触发了发布，不说明当前 HEAD，也不会重新访问仓库。验收备注、请求键、审批键、远端地址和原始错误不展示。

## 会话通信

每条记录对应一条消息。只展示两端会话都可读且仍属于同一项目的通信；首版不列外部或尚未解析到会话的端点。只有 Hub 写入的交接来源标记才显示「项目交接」，只有精确的回复 ID 且关联消息本身也可读才显示回复关系。投递、读取时间来自消息记录，不代表接收方已经开始或完成了 Agent 回合；不展示正文、附件和原始错误，也不把两种记录按时间拼接。

## 机器连接

一条记录对应 Hub 接受的一条连接；只记录有本机证明或以专属凭据通过认证的连接。断开沿用同一个连接 ID 与登记身份，旧连接的关闭不会改写重连后的记录。Hub 未观测到断开时，显示「未记录断开」，不宣称机器仍在线。记录不属于某个项目；本机记录按本机权限查看，远端记录必须匹配当前有效的登记身份和访问权限。只有 Hub 向该连接发送的运行时安装任务在同一连接上明确报终态，才在连接详情显示成功或失败；重复报告不另记，断线不算失败，不回显安装日志。共享令牌连接、旧历史及 Worker 更新结果不会用当前状态补造。连接记录在新事件时清理旧行（约 30 天，最多十万条）；安装报告单连接至多 100、全局至多十万，清理后标明截断。

### 首条输出

- Hermes Runs：只认新提交、首次连接的原始运行流；内部重试、恢复流或无法归属时不标记。
- Codex：只认响应绑定后的同线程、同回合、带原生条目 ID 的非空正文。正文先于绑定到达或身份不明时照常写入，但不把后续片段标成首条输出。有送达 ID 的回合也只接受当前线程的生命周期通知；旧无键回合兼容缺少线程 ID 的通知。
- Hub 只保留与同会话在途送达精确相符、且在结束前的标记。页面展示 Hub 记录时间，不展示正文，也不把它当作模型耗时。其他运行时和旧历史缺少可信证据时仍显示「未记录」。

## 接下来补哪些证据

| 环节 | 已有权威记录与取证限制 |
| --- | --- |
| 派工与验收 | 调度、派工作为独立来源；派工详情显示有权限的历史验收和发布尝试。只链接持久化标识明确且当前可读的会话；已准备不等于执行完成，已验收也不等于已发布。 |
| 连接器与会话交接 | 连接器触发与任务请求用已保存的唤醒键；消息使用明确的消息 ID 和回复关系。没有消息到送达的持久关联时不画边。已保存的画布连线也不是调用关系。 |
| 运行过程 | Hermes Runs 和 Codex 的部分回合可记录首条输出；其他运行时、工具调用、审批、子 Agent 与用量仍需可归属的事件。没有准确回合标识的日志不补挂；不能可靠配对的时间戳不生成耗时。 |
| 机器 | 已有经认证的连接历史；即时资源和更新任务状态不等于历史事件。「发出了更新请求」不能显示成「更新成功」。 |

## 验收

- 用真实本地 Hub、配对 Worker 和可暂停的测试 Agent：保持 A 运行时提交 B，验证 B 仍排队；放行 A 后，A 的结束不能记到 B 上；最后单独放行 B。
- `node:test` 覆盖旧记录、未知结果、分页边界、多项目隔离和直达详情授权；Playwright 覆盖来源切换、连接器原入口及手机列表。未采集到的阶段不算通过。
