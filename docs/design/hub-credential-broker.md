# Hub 托管凭证：先让 Agent 读项目仓库

状态：首版在 worktree 实现，满足启用条件时默认开启，尚未部署或开通隔离试点。与 [项目 Git 隔离原型](project-git-access.md) 配合阅读；原文记录独立验证过的抓取与对象交付机制，不是本工具的执行路径。

## 1. 用户要的是仓库能力，不是凭证

用户说「看一下当前项目 API 仓库的 `main`」，Agent 请求读取，Hub 根据会话所属项目找到目标仓库并代读。成功返回**读的是哪个仓库、哪个分支、当时的提交和内容**；Agent 不需要知道地址、在哪台机器认证、用的是哪把凭证。换一台无 Git 凭据的 Worker，已授权的读取能力不变。

**凭证只在 Hub 信任边界内保存和使用；按资源授权复用，不按凭证试错。** 例如团队保存一次「代码托管只读」，分别授权 `api` 和 `web` 使用；没有绑定的 `infra` 不会尝试这一凭证。普通用户不看凭证清单，Agent 不接收凭证值、名字、句柄或可代用的通用代理。访问方配置是 `Hub 托管 / 公开无凭证 / 机器凭据（兼容）`，每个操作沿已配置方式执行，失败不相互兜底。首版只有新的 **Hub 托管 HTTPS 只读** 路径；公开及机器凭据的旧流程不迁移。

## 2. 架构：凭证管理是 Hub 内模块，不是独立服务

首版在 `apps/server` 装配一个 **Hub 凭证管理模块**。它同时负责托管和代办，不新增部署单元、通用执行 API 或 Worker 协议。可以复用现有加密存储与 SQLite，但托管凭证用独立命名空间；密钥库、明文读取及可由调用者传入任意回调的取密钥接口不导出给通用 `Deps`、工具、插件、资产展开或 Worker 调度。

| 模块内部职责 | 边界 |
| --- | --- |
| 管理与保管 | 接收经鉴权的新增、轮换、撤销及绑定操作；管理版本和加密值。设置页只读有权查看的元数据。 |
| 授权与代办 | 接收结构化业务动作和已验证调用者，复核当前会话、资源、目标和动作；唯一匹配后才使用凭证。交付前再次校验，统一审计。 |
| 业务适配器 | 由 Hub 注册。首版只有 Git HTTPS 的检查与快照读取；负责协议、确切目标限制、配额和结果转换。只在模块信任边界内获得完成当次操作所需的认证能力，不提供通用出站代理。 |

调用链：**Agent → 会话 MCP → Hub 仓库用例 → Hub 凭证管理模块 → Git HTTPS 适配器 → 已登记仓库**。项目设置走同一个模块管理绑定、检查访问。两条入口的身份和授权不同；都不返回凭证明文。Worker 只接收获准的业务结果，不负责远端认证，也不因换机而替换凭证。

**代码边界不等于安全边界。** 在 Hub 使用专用非特权账号、不执行 Agent、Worker 无法访问 Hub 存储或进程的部署中，凭证模块可以和可信 Hub 同进程；它不是防同进程恶意代码的沙箱。当前阿里云仍由 Hub 拉起本机 Worker，首版保持关闭，也不录入真实托管凭证。试点先用独立 Hub＋外部 Worker，操作员入录凭证须经加密管理入口。若要在现有部署启用，须先确认本机任务和工作目录的处置，再迁至隔离部署；关内嵌开关、只改目录权限或另起同账号进程都不构成完整验收。拆出凭证微服务不作为首版前置。

## 3. 首版交互

### 项目设置：保存一次，分别授权

沿用「项目设置 → 代码与工作目录 → 仓库」。在**已登记**的仓库行选择「Hub 托管」，从有权使用、与认证类型及服务端点匹配的凭证中选择，或新增并绑定为「读取仓库」。先保存仓库目标和绑定，再提供「检查读取」；不拿保存的凭证试尚未保存的地址。检查成功仅表示**该时间、该地址、该凭证版本能读**，不代表能写；改变地址、分支、认证或凭证版本后，旧结果失效。

首版由同时具备团队和项目管理权限的维护者新增、绑定、轮换、撤销；可选凭证限同团队和同 HTTPS origin。Agent 有权调用已有绑定，不等于有权建立绑定。界面只显示可用凭证的名称和版本等元数据，明文只写不回。撤销共享凭证与解除单仓绑定是两个动作；不做跨团队共享或单独的运维控制台。

### 会话：优先不问，确有歧义只问仓库

| 情况 | 默认行为 |
| --- | --- |
| 任务明确指定仓库 | 在当前会话获准的项目仓库范围内解析；不解析任意 URL。 |
| 已有明确对应仓库的工作目录 | 默认这个仓库。历史归属、目录名或当前 `origin` 单独都不能证明对应关系；绑定失效就提示，不暗换其他仓库。 |
| 本就没有仓库绑定，且当前项目只有一个获准仓库 | 默认这个仓库。多仓项目不因为某仓连接失败、未绑定凭证等运行状态变化而自动换仓。 |
| 有多个候选或对应关系不明 | 仅在确有歧义时确认，工具返回当前项目的登记候选，由 Agent 在后续调用中显式指定；不持久化会话偏好，也不把清单第一项当作主仓。 |
| 没有工作目录／「仅对话」 | 启动时仍不联网、不下载、不跑准备命令。经授权且实际请求远端读取时，可以返回**远端快照**，不创建目录、不改变 cwd。需要改代码、运行测试时再显式准备目录并从该目录启动会话。 |

桌面和手机均通过「项目能力 → 读取项目仓库」授权。首版不做常驻仓库选择器或会话偏好存储：不能确定目标时，工具返回当前项目的仓库候选，Agent 按任务上下文确认后显式传 `repo_id`。结果包含仓库、分支、完整提交 SHA、读取时间和 `localFilesUpdated: false`。本地文件读取仍走现有工具（可包含未提交改动），不能当成远端快照。新增授权后需让 Agent 重新获取工具列表；撤销会阻止后续操作，也不会交付仍在处理的未授权结果。

## 4. 通用的是授权与执行，不是万能密钥接口

三个对象分开：

| 对象 | 负责什么 |
| --- | --- |
| 凭证记录 | 团队内稳定 ID、类型、提供方／租户、外部身份、允许使用的服务端点、状态和版本；值单独加密保管。首版用专用只读服务凭证，不把个人登录身份作为团队兜底。凭证 ID 不是授权。 |
| 资源绑定 | 在何团队的哪项资源、对哪个确切目标与哪类操作、可用哪份凭证。Git 首版是 `(teamId, projectId, repoId, exact HTTPS target, repo.read)`，一次操作只有一个有效绑定。跨团队不复用；跨端点不是默认权限。 |
| 受控操作 | 解析已验证调用方、当前会话、当前项目、资源及动作；执行业务动作，返回有界结果和审计回执。不提供 `getSecret`、任意 URL 请求或任意命令入口。 |

**首版接口：**会话 MCP 的 `project.repo.read({ repo_id?, branch?, path?, expected_tip? })` 每个目录最多 1,000 项，单个 UTF-8 文本最多 64 KiB，路径省略读根目录。省略分支取已登记默认分支，未配置时尝试确认服务端默认分支；`expected_tip` 只比较这次读取到的分支提交，不授予任意 SHA 的读取权。请求没有 `projectId`、URL、凭证或 Worker 参数。管理端连接检查和会话读取复用同一目标／凭证策略，但各自验证调用者权限；读仓库需独立的 `repo:read` 授权，不随 `project:read`、普通 Git 工具、Bot、共享会话或子会话自动继承。

Hub 在执行前并在结果交付前复核授权、目标、凭证版本；先用元数据找到唯一授权绑定，再解密。撤权后不发起新访问，执行中的旧结果不再交付（已经交付的内容无法收回）。绑定、有效版本和检查状态用原子更新，失败不留下半套配置。可以复用现有加密存储实现，**不直接把既有资产、模型、Git 托管平台的表合成 Agent 可试用的密钥池**。轮换是同一外部身份的新版本，由维护者验证并切换；换外部身份须重授权，不能因认证错误自动换账号、回退旧版本或换协议。将来接入 SSH、制品库或工单服务时，分别定义其目标验证、操作权限与结果契约；不是放开通用代理。

## 5. 真实隔离才算交付

- 带凭证的 Git 只在与 Worker／Agent 隔离的专用 Hub 身份和私有存储中运行，不读 Agent 可改的仓库配置、环境或 helper；目标由服务端从登记配置解析，按协议、主机、端口和路径精确绑定，禁止重定向。复用 [隔离原型](project-git-access.md) 的出站约束、真实资源配额和专用身份。凭证值不进 Worker RPC、Agent 环境、工作目录、浏览器响应或日志；同账号换进程不等于隔离。
- 首版直接在 Hub 受控暂存中读取已验证 Git 对象的目录／文本，不导入 Worker、不递归子模块、不 checkout，不动 `HEAD`、索引、远端跟踪引用或未提交文件。不跟随仓库内链接到执行器文件系统；二进制、超限、无权限等明确返回，不伪造成功。以后「下载到目录」或「交付候选对象」需要独立动作和验收，不借用现有导入原型伪装无目录会话。
- 结果只暴露必要的访问状态。连接失败与确证缺分支分开；首次失败不推断凭证失效。审计关联操作者／会话、项目、资源、动作、凭证版本标识和结果，不记内容、原始 Git 输出或明文。授权失败不能泄露其他团队或未绑定凭证是否存在。
- 恢复演练须同时验证数据库和主密钥可恢复，并分别保护两者；现有数据库快照不是主密钥备份。已有记录但密钥缺失或不可解密时，托管操作关闭并报运维错误，不自动生成新钥替代原钥。
- 既有 Worker 的 Git/SSH、模型和资产的密钥传递不在本次隔离保证内；旧凭证若曾下发，需要换发、撤销旧值，移动存储不能收回副本。新路径的默认值不豁免隔离检查；当前内嵌 Worker 的部署不能当作验收依据。首个试点采用独立 Hub＋外部 Worker，实际验证 Agent 身份无法读取 Hub 凭证，以及暂存硬配额生效后再提供真实凭证。

### 启用门槛与兼容行为

- 不设置 `HUB_CREDENTIAL_BROKER` 时自动检查并启用，`1` 同默认行为，`0` 显式关闭。值无效或启用条件不满足时不打开凭证库或注册读取工具，管理入口返回 JSON 404。Hub 须以非 root 专用账号、回环监听且 `HUB_SPAWN_WORKER=0` 运行；操作员须保证 Worker 不与 Hub 共享进程可见性、数据目录或运行身份，并由专用 TLS 入口覆盖转发头，不得让不可信代理或进程直连回环监听。功能开启不等于向会话授予读取权限。
- `HUB_CREDENTIAL_ADMIN_ORIGIN` 配置精确 HTTPS origin；`HUB_CREDENTIAL_GIT_ORIGINS` 和 `HUB_CREDENTIAL_PROJECTS` 分别配置逗号分隔的出站 origin 和项目白名单。`HUB_CREDENTIAL_SCRATCH_ROOT` 必须是独立、Hub 私有、总量不超过 128 MiB 的 tmpfs 挂载，且与数据目录互不包含。主密钥是数据目录内专用的私有 `hub-credential.key`，使用 32 字节的标准 Base64 编码；缺失或不匹配会保持关闭。
- 管理要求在配置的 HTTPS 入口以密码登录、邮箱已验证、当前团队 owner/admin，且有对应项目管理权。此角色组合是首版共享凭证的委派边界；没有开放单独的凭证委派管理。更改已保存的仓库清单、兼容目标或项目归属会解除该项目的绑定，凭证和其他项目的绑定保留。轮换或撤销作用于凭证的所有绑定，解除绑定只影响当前仓库。

## 6. 后续工作与试点验收

现有兼容路径的安全补丁仍独立待办。首版只读代码已接入：自动化覆盖加密存储、权限和在途变化、真实 Git 快照运算；桌面／手机浏览器覆盖真实 Hub 缺少启用条件时的行为及模拟启用后的管理交互。这些不替代独立 Hub、外部 Worker、TLS 入口与暂存配额的实际验收。下列验收仍是启用试点的前提。

1. **兼容路径独立修复。** 旧工具的目标、项目归属、仓库准备和配置原子性问题不由新读工具解决。
2. **用实机验收 HTTPS 只读闭环。** 用隔离 TLS 测试仓库、无凭证外部 Worker 和真实 Hub/MCP 跑通绑定 → 检查 → 会话读取 → 轮换／解绑，确认两个绑定可复用同一凭证、撤权后旧结果不交付，完整复验隔离、配额、数据库和主密钥恢复以及无工作区副作用。隔离或配额不达标时保持关闭，不回退旧入口。
3. **按用例扩展，不先做平台。** 显式准备受管目录和对象交付另立增量；需要 SSH 或其他服务时再加适配。远端推送与 PR 另立授权，固定仓库、目标分支、完整提交 SHA 和动作，保留人工批准；Git 写凭证与 PR 平台 API 权限各自绑定。现有 `git.push`／`git.pr` 和机器 shell 的权限不因本提案自动收紧。
