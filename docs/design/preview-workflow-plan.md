# 远程预览与调试闭环：优化计划

范围：本轮实现 P0/P1，本地验证；未部署。沿用原有转发和权限，不建设云浏览器（P2）。

## 目标与现状

用户不必抄端口，就能从当前会话打开自己刚启动的页面；打不开时知道问题发生在哪；看到问题可以带着页面路径回到原会话。借鉴 Orca [Browser](https://orca.dev/docs/browser/overview) 和 [Design Mode](https://orca.dev/docs/browser/design-mode) 的「工作上下文 → 预览 → 反馈」闭环，不照搬它的浏览器容器或移动端远程操作。

Agent Hub 已有[预览传输与鉴权](preview.md)。旧模型的 `ready` 可能只是链接已登记或 Worker 正在监听，不能证明 HTTP 有响应，更不能证明用户设备能访问映射端口。本轮在会话页、画布内会话和本地服务卡片共享入口，并由服务端提供独立的映射和诊断证据。

## P0：一键打开、诊断到层

```text
桌面：会话/本地服务 → ⋯ 预览 → 找端口/打开  →  会话/本地服务：[打开预览] [更多]
手机：⋯ → 预览 → 选端口 → 打开             →  会话正文旁：[打开预览]，多项才弹选择面板
```

- 会话页和画布复用一个入口逻辑；已有「本地服务」卡片的快捷动作指向同一目标，不在每条 Agent 回复旁重复加按钮。仅一个已匹配目标时直开；多个时展示名称、机器和状态供选择，不默认选第一个。无目标时保留「重新检查／手动添加端口」，不把 Agent 文本中的任意 URL 当成可访问目标。
- 优先复用当前会话的私有预览链接；已知服务尚无链接时，由「打开预览」发起现有权限范围内的幂等登记并打开。服务候选必须能关联到当前会话、同一 Worker 和已验证的端口证据；同端口不同 Worker 不匹配，不把孤立进程、其它目录或后端依赖自动发布。创建等待或回执丢失时先查已有结果，不自动另建、换端口或重发。保留浏览器的显式打开按钮，避免异步操作被浏览器拦截后无反馈。
- 使用当前部署实际配置的预览入口和协议，直接在浏览器打开。独立端口仍走 HTTP/WS；HTTPS Hub 的私有登录 Cookie 不会发送给 HTTP 预览端口，界面说明该限制，不自动公开分享、不退回不安全的登录或同源路径。手填端口、复制私有链接和显式公开分享仍在预览管理中。不修改安全组、域名或分享协议。

### 状态与证据

| 界面反馈 | 可以依赖的证据 | 不据此推断 |
| --- | --- | --- |
| 等待检查／未能确认 | 无新鲜样本、请求超时或检查仍在进行 | 服务未启动或页面正常 |
| Worker 离线／预览通道未连通 | 当前 Worker 连接或预览通道状态，分别判断 | 远端进程已退出 |
| 预览目标未监听 | 代理对实际目标明确连接被拒，或可靠且覆盖该地址族的新鲜端口快照确认未监听 | 扫描失败或空快照不等于未监听；IPv6 监听不证明 IPv4 回环可用 |
| 预览入口未就绪 | Hub 已知监听失败、端口分配失败或未配置访问入口 | 用户设备网络不可达；该判断必须有浏览器侧证据 |
| 页面已响应／页面返回 `4xx` 或 `5xx` | 经同一预览转发收到的实际 HTTP 响应；明确是应用状态还是代理失败 | 页面及其子请求全部正常；应用的登录要求不是 Hub 鉴权失败 |

实现时将「链接存在／监听」和「请求结果」分开，暂不重写持久化 `PreviewLink.state` 和旧契约；为当前会话投影一个附带时间的诊断结果。优先复用正常导航返回的代理分类；需要主动检查时，仅对已授权的链接走既有转发和约定的只读健康路径，不携带用户 Cookie 或令牌给上游，不探任意 URL、不跟随重定向，限制超时、并发与读量，仅返回状态分类。按会话、链接和当前通道隔离短期结果，切换或重连后丢弃迟到结果。Hub 内部检查不能标成「你的设备可访问」；跨源、TLS 或网络失败无法分类时，只提示用户确认访问路径，不猜根因。

以「前端代理 `/api` 到后端」为例：前端首页返回 `200`，并不能证明后端通。本轮诊断固定用 `HEAD /`，不请求 `/api`、不跟随重定向，不把表单或登录结果当成配置建议。子请求结果以真实页面请求或用户反馈为准，不建议额外映射后端。P0 不做通用的页面网络检查器。

## P1：把现场带回原会话

- 「反馈到对话」回到发起预览的会话，往现有草稿追加预览名称、页面路径和复现说明，不覆盖已有草稿、不自动发送。手机先用系统截图和现有附件入口；桌面复用相同草稿逻辑。路径取用户确认的当前路径：原生跨源标签页不能被 Hub 静默读取；没有可靠信号时让用户填写。
- 按账户、会话和链接保存最后一次已明确选择的路径，链接失效则回到选择。只保存同一预览 origin 内的相对路径，默认不带查询串、片段和分享令牌；不自动采集页面 DOM、控制台、网络内容或凭证。

## P2：按使用反馈决定是否做内嵌

仅在用户频繁来回切换、或反馈仍缺关键定位信息时推进：桌面对话旁增加单预览面板，手机使用全屏并保留明确的返回入口。需先评审独立预览 origin、嵌入隔离和授权，不能默认移除站点安全限制或给上游页面 Hub 同源权限。保留「在浏览器打开」；元素点选和控制台采集另行设计，不是本轮验收项。

## 实施与验收

| 顺序 | 代码边界 | 发布条件 |
| --- | --- | --- |
| 1. P0 状态契约 | `apps/server/src/{wire-preview,preview-channel,preview-proxy,preview-routes}.ts` 与共享 DTO；复用 Worker 已有扫描和转发 | 先验证诊断来自正确层；未升级 Worker 或无证据时允许降级为「未确认」，不给假成功 |
| 2. P0 共享入口 | `apps/web/src/atoms/{preview-panel,services-section}.tsx` 和会话／画布入口 | 桌面和手机同语义；保留旧预览面板和手动打开作为退路；先在隔离环境验证后再启用新入口 |
| 3. P1 反馈草稿 | 预览返回、会话定位、现有 composer 草稿与附件 | 在 P0 稳定后做；验证回到原会话、内容仅追加、无自动发送 |

- **后端验证**：复用 `preview-routes`、`preview-channel`、`preview-proxy` 的测试，新增注册不等于可达、旧结果丢弃、未授权无检查/无副作用、同会话同端口重复打开仍只有一条私有映射的回归。
- **端到端**：扩充 `e2e/preview.spec.ts`，用独立 Hub、真实 Worker、监听随机回环端口的测试前端和上游 API；桌面 1280px、手机 390px。覆盖自动发现后点击一个入口、两个候选需选择、Worker 断开、停止前端、只停后端（首页仍 `200` 且约定的 API 路径报错），另验一个超时或丢回执场景。确认无需手填端口、只建立前端映射、未授权打不开、没有生成公开链接。端口级代理的公网可达性与应用业务单独验证，不用主 Hub `/api/health` 代替。
- **回退**：`HUB_PREVIEW_WORKFLOW=0` 停用新入口和诊断，保留原手动面板、已有链接、分享状态和权限。旧 `HUB_PREVIEW_AUTO` 不再控制发布；无论配置如何，都不恢复由输出或扫描直接发布端口。不随本计划变更生产端口或防火墙。执行发布前按[仓库验收文档](../testing/README.md)验证最终 Git 树，并另约测试会话和目标 Worker 做生产业务冒烟。
