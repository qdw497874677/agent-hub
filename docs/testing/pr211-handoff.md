## 本轮修了什么

架构收敛和 Hub 统一供应商是同一条 PR 上的事，没有另开产品默认。

- 可观测只读、送达认领、文件限流和若干收敛提交已经在这条分支上。细节留在 PR 说明的历史段落，不在这里重写。
- 供应商由 Hub 管理：作用域个人 / 团队 / 全站。密钥加密进库，创建和更新的 HTTP 响应不带回 `apiKey`。会话要显式选 `hub-<标识>/<模型>` 才走这家供应商。空模型仍是 agent 自己的默认，不会自动改成 Hub 模型。
- 本轮验收的 GLM 只有国内智谱 Coding `glm-5.3-flash`，Base URL `https://open.bigmodel.cn/api/coding/paas/v4`，标识 `cn-glm-flash`，协议 `openai-chat`，路由 `direct`。模型 id 是 `hub-cn-glm-flash/glm-5.3-flash`。
- Go 不在本轮验收里。若以后要用 Go，只允许 DeepSeek V4.1 Flash。GLM 不得落到 Go，空模型也不得落到 Go，不得改用按量付费基址。`docs/testing/opencode-go-pi.md` 记录的是 Pi 1.4.0 怎么读 Go，不是本轮的放行。
- 没有原生模型、但 agent 报了协议且已有同协议 Hub 模型时，可以先选机器和工作空间，再在真实控件里选模型。「开始」在没选模型时仍是灰的。未安装、检测失败照旧拒绝。
- 会话卡片的模型候选项会带上这次显式选中的 Hub 模型，避免原生清单为空时控件不出现。
- 开放 API 使用 Hub 模型必须另带 scope `providers:use`。它包含 `provider.read` 和 `provider.use`，不含 `provider.manage`，也没有并进 `sessions:write`。没选这个 scope 就拒绝。选了也要本人角色本来有权。viewer 勾了也不通过。别人的个人提供商、别的团队的提供商照旧拒绝。令牌打本机 Worker 先 403，不把这次拒绝说成「未配置模型」。

## 剩余问题

按下一步要的证据排。没有证据之前不要改产品。

1. **用量计数。** `0cfc530` 这次已经有 91 条原生 usage 和真实回复，`provider_usage` 的 request / errors 仍可能是 0。同一行的 sessionCount 是会话数，不是请求数。中转路径会计请求；direct 下发到 worker 的路径目前不在 Hub 上累加 request。先拿同一条会话的原生 usage、`provider_usage` 行和路由再决定要不要记 direct。不要用这个 0 写成没有流量。
2. **检查点 503。** 早期 3 次没有响应正文，也没有 kill / delete / exit 的时点，原因仍未知。`0cfc530` 的检查点没有 503，这不是那 3 次的根因修复。若再出现，要同一次日志里的 HTTP 状态、正文、`ckpt-diag` 的阶段和 worker 退出时点。没有这些就不要再单跑这条。
3. **阿里云旧全套。** 结果未知。本轮不 SSH、不把那次写成通过或失败。若要补，在那台机器上用新的数据目录重跑，并单独记录。
4. **Langfuse 与生产。** 没有接 Langfuse live，没有生产验证。部署未授权。
5. **覆盖。** 122 条通过不是全覆盖。假 ACP、Hermes 本地假网关、故意删目录的 182 条失败，都不能写成模型成功。46 次和 3 次采样也不是穷尽证明。
