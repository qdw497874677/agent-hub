# ADR 0034：工作空间上的本机服务预览

- 状态：**proposed**（2026-11-09，供审阅，未实现，未合并，未部署）
- 相关：ADR 0002（不分发 Docker）、ADR 0011 / 0017（`can()`）、ADR 0025（文件经 worker RPC，有大小上限）、ADR 0026（工作空间是团队资源，可关联多个项目）、ADR 0030（worker 长连接与能力声明）、[详细设计](../design/service-preview.md)

## 背景

多机开发时，会话跑在某台 worker 的某个目录里，人经常在那台机器上起一个只听 `127.0.0.1` 的网页（Vite、Next、测试桩）。浏览器在另一台机器上，打不到那个地址。Hub 今天能看会话和文件，不能打开这个网页。

这不是部署，也不是把服务公开到网上。关掉预览不应该杀掉那个进程。

## 决定

1. **服务归工作空间，不归会话。** 一条登记是「这台 worker 上这个目录的这个本机端口」。`sessionId` 只做来历，可空。一个工作空间可以有多条登记，MVP 建议上限 8（可调）。
2. **只接受显式登记的本机端口。** worker 只连接 `127.0.0.1`（或 `::1`）上的该端口。拒绝任意 URL、任意 host。低于 1024 的端口，以及 worker 自己监听的中继、MCP、Hermes 网关端口，登记失败。登记不是沙箱，不能说登记一次就绝对安全。
3. **多项目工作空间不能按其中一个项目授权。** 长期工作空间关联了两个及以上项目时，登记和打开都要团队级 `workspace.manage`。只关联一个项目，或临时工作空间，才允许对该项目有 `session.create` 的人登记和打开。viewer 默认没有这两项。权限名是建议，现在的目录里还没有。
4. **服务 id 稳定，generation 单调递增。** 预览票据和预览会话都绑 generation。端口从不可达变为可达、用户撤销或改端口、worker 控制连接重新建立时，generation 加一，旧票据和旧预览 cookie 失效。这缩短「旧授权打到新进程」的窗口。worker 连出到一个 TCP 端口，**证明不了**监听者的进程身份；不把 `/proc` 或 pid 当成归属证明。
5. **控制面沿用现有 `/worker` RPC，数据面另开一条 worker 主动拨出的隧道。** 不把网页字节放进现有 JSON RPC、base64 或 outbox。
6. **每个预览一个独立 host，并且这个 host 不能和 Hub 共用 cookie host。** 优先用另一块可注册域上的通配名。Cookie 不按端口隔离：`127.0.0.1:7878` 和 `127.0.0.1:别的端口` 会共享 cookie。没有安全的独立 host 时，预览禁用，不做 Hub 同源路径反代，也不用「多开一个端口」冒充隔离。
7. **浏览器默认新标签打开。** iframe 嵌入 Hub 页面不是 MVP。关掉预览或关掉标签只拆转发，不向该进程发信号。
8. **不改写 HTML。** 不承诺任意站点透明可用。绝对地址、重定向到别的 host、应用自己的 CORS，由应用配置解决；转发器拒绝把浏览器带到未登记的 host。

## 后果

- 正面：授权的人能在自己的浏览器里打开 worker 上已经在听的本机网页；两台机器同端口不会串；Hub 的登录 cookie 不会因为预览页而变成那个应用的脚本可读。
- 负面：没有独立预览域的自托管，MVP 里没有预览。worker 重连会使已打开的预览失效，需要再点一次打开。本地服务若自己不鉴权，被授权的人就等于站在那台机器的回环地址上。
- 未做：自动发现端口、公开链接、代杀进程、HTML 改写、iframe。

## 备选（不采用）

- 挂在 Hub 路径下反代：预览应用的脚本与 Hub 同源，能读非 httpOnly 的 `hub_csrf`。
- 只换 Hub 机器上的端口：cookie 仍按 host 发送，给不出隔离。
- 把字节塞进现有 RPC：一帧 JSON、默认 60 秒、base64，撑不起流、上传和 HMR。
- 浏览器直连或 SSH 本地转发：NAT 后的 worker 没有入站；也不走团队授权。可以继续当个人权宜之计，不进产品。
