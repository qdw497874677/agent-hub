# 11. 团队 + 集中授权（RBAC）

Status: accepted（2026-10-29；David 22:25 / 22:27 / 22:29 决定；实现见 #101、#102 和审计 PR；设计见 docs/design/user-management.md）

## 背景

ADR 0008 的账号「不做资源隔离」：任何成员都能删任何项目（默认项目就是这样没的），也能在 hub 服务器自带的「本机」Worker 上开会话，等于拿到服务器 shell。授权判断散在 admin / enrollment / runtime-install 三处，其余路由默认全放行。评审见 docs/design/user-management-review.md（review/user-management，7fc4e9d）。

## 决定

1. **权限是数据**：`packages/domain/src/access.ts` 里 `Permission` 是一组字符串，`ROLE_PERMISSIONS` 把角色映射到「权限 → 范围（team / own）」。新增角色只改这张表（和 `Role` 类型），不改路由。
2. **唯一的判断入口 `can(principal, permission, resource)`**，配 `visible()` 过滤列表。HTTP 路由不写角色判断；权限矩阵测试（access.test.ts）把表钉住。
3. **团队**：每个用户恰好属于一个团队。成员看自己的资源 + 共享给自己的；团队主人看团队里全部。hub 超级管理员（David）另有 `hub.*` 权限；不在自己团队的资源对他同样按 hub 权限放行。
4. **老数据迁到 David 的团队**（启动时幂等回填）。
5. **「本机」Worker**：只有 hub 管理员和被单独授权的 hub 团队成员能用；`can()` 和派发两处都检查。
6. **注册默认关闭**；自助注册的人得到自己的空团队；注册不泄露邮箱是否已存在。
7. **邀请**：团队主人邀请，带角色，加入邀请人的团队；收信点链接即视为邮箱已验证。邀请计入 `HUB_MAX_USERS`，主人可勾 `allowOverLimit` 越过。
8. **删除成员**：软删 + 匿名化（邮箱 / 显示名改写、密码与登录作废），名下项目转给团队主人。
9. **删除项目进回收站**（软删），可还原 / 彻底删除，磁盘目录都保留。
10. **登录防爆破**：每邮箱前 5 次失败免费，之后指数退避 1 秒起、最多 15 分钟，成功即清零，永不锁死；另有每 IP 限流（15 分钟 30 次）。
11. **个人设置**：改密码要旧密码，成功后踢掉其他登录并发通知邮件；改显示名。
12. **安全审计**：登录成功 / 失败、退出、注册、重置 / 修改密码、改资料、邀请、删人都进审计，记来源 IP 和所在团队。后台可按动作、操作人、IP、时间筛选；团队主人在「我的团队」里只看自己团队的。

## 后果

- 所有新路由必须走 `can()`；漏掉的会在权限矩阵测试或 e2e 里暴露，而不是默认放行。
- 退避状态只在进程内存里，重启就清零（与现有限流一致）；多实例部署时要换共享存储。
- 匿名化不可逆；审计里保留的是匿名后的 id，不能再反查到原邮箱。

## 未决问题（先按最简单的做了）

- 不能删除团队主人（要先有转让主人）。
- 被删成员登记的 Worker 留在团队里，不转移也不吊销。
- 已有账号的邮箱不能被邀请（不做跨团队迁移）。
- 未知邮箱的登录失败也记审计，操作人 id 为空。
- 工作空间清理（sweep）不按团队划分。
- `backfillProjectTeams` 每次启动都跑一遍（幂等，代价小）。
- 勾了 `allowOverLimit` 的待接受邀请不占名额。
- 后台（hub 管理员）的用户操作（停用等）审计不带 teamId，团队主人看不到。
- 团队审计用 `audit.read` 权限（现在只有 owner 有）。
- 团队成员管理放在账号菜单的对话框里，没有单独的 `#/team` 路由。
